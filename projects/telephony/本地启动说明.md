# 本地启动说明

以下命令依据包内 `package.json`、Prisma 配置和 Go 模块文件整理，用于新环境准备。此次交付做了源码静态核对，未在空白机器执行完整安装与外呼验收。

## 依赖

- Node.js 满足根目录 `engines`：`^20.19 || ^22.13 || >=24`。
- pnpm 使用根目录指定的 `11.25.0`。
- PostgreSQL、Redis；本地开发可用包内 Docker Compose 启动。
- Go `1.25.0` 或兼容版本，用于编译 SIP 语音桥。
- 实际 AI 外呼还需 FreeSWITCH、SIP 线路、语音桥内部凭据和模型账号配置。

## 安装前后端依赖

在解压后的源码根目录执行：

```sh
corepack enable
corepack prepare pnpm@11.25.0 --activate
pnpm install --frozen-lockfile
```

如果操作系统没有 Corepack，可通过现有 Node 包管理方式安装包内指定的 pnpm 版本。保留 `pnpm-lock.yaml`，便于复现依赖。

## 准备本地配置

```sh
cp apps/server/.env.dev.example apps/server/.env
cp apps/console/.env.local.example apps/console/.env.local
docker compose -f docker-compose.dev.yml up -d postgres redis
```

检查并填写后端 `.env` 中的 `DATABASE_URL`、`REDIS_URL`、`BETTER_AUTH_SECRET`、`INTERNAL_API_KEY`、`SECRET_ENCRYPTION_KEY` 等字段。示例里的 `dev-...` 和 `replace-...` 是占位值。登录加密、存储和供应商配置需使用本环境自己的值。

前端的公开地址在构建时读取。更换部署地址后重新构建前端：

```dotenv
NEXT_PUBLIC_SERVER_URL=http://localhost:5000
NEXT_PUBLIC_CONSOLE_URL=http://localhost:3000
NEXT_PUBLIC_API_VERSION=v1
```

知识文件、录音资产、知识检索和实际通话相关依赖，应按准备使用的功能配置；原有环境示例和代码保留了多种供应商入口。

## 生成数据库客户端与表结构

在源码根目录执行，确认 `apps/server/.env` 指向自己的本地数据库：

```sh
pnpm --filter server exec prisma generate
pnpm --filter server exec prisma migrate deploy
```

Prisma 客户端输出到 `apps/server/prisma/generated/prisma`，这个生成目录不在源码包中。初始化账号与基础数据前，先阅读 `apps/server/prisma/seed.ts` 和 `deploy/taigua/bootstrap.ts` 的具体内容；包内没有现有员工账号或业务数据库。

## 分别启动界面和 API

打开两个终端，在源码根目录分别执行：

```sh
pnpm --filter server dev
```

```sh
pnpm --filter console dev --port 3000
```

浏览器访问 `http://localhost:3000`。后端示例地址为 `http://localhost:5000`。前端与 API 地址、允许来源、登录回调应互相一致。

## 定向构建

```sh
pnpm --filter server build
pnpm --filter console build
```

构建前端前应已生成 Prisma 客户端。若从全新目录直接做前端类型检查，`.next/types` 尚不存在；Next 开发或构建阶段会生成这些类型。

本包只交付电销应用及所需共享代码，使用以上定向命令。上游根脚本中的官网 `web`、SEO 操作、其他应用的测试和整仓开发编排，依赖本包范围之外的目录。

构建完成后可分别运行：

```sh
pnpm --filter server start
pnpm --filter console start --port 3000
```

## 编译语音桥

进入 `services/sip-bridge`：

```sh
go mod download
mkdir -p bin
go build -o bin/sip-bridge ./cmd/bridge
```

语音桥和 API 是两个服务。主要连接字段如下，具体校验与默认值见 `cmd/bridge/main.go`、后端 `modules/telephony/bridge-client.ts`：

| 字段 | 用途 |
| --- | --- |
| `SIP_BRIDGE_URL` | API 访问语音桥的本机 HTTP 地址 |
| `SIP_BRIDGE_TOKEN` | API 和语音桥一致的内部访问凭据 |
| `SIP_CALLBACK_URL` | 语音桥向 API 回传事件的地址 |
| `SIP_ESL_ADDR`、`SIP_ESL_PASSWORD` | FreeSWITCH ESL 连接 |
| `SIP_MAX_CALLS` | 语音桥容量预算 |
| `SIP_LIVE_ENABLED` | 是否允许真实执行外呼 |
| `SIP_REALTIME_MODEL` | 实时模型选择 |
| `TAIGUA_MODEL_ENV_FILE` | 语音桥读取模型作用域凭据的配置文件 |
| `SIP_STATE_DIR`、`SIP_RECORDING_DIR` | 状态与录音存储目录 |

FreeSWITCH 和线路商配置不在这个 Go 模块内，需在目标服务器准备；仅编译成功不能证明线路已经接通。

## 生产迁移时需另行准备

源码之外还有数据库备份、音频与文件资产、生产环境变量、反向代理、进程管理配置和 FreeSWITCH 配置。包内 `deploy` 保留原有脚本以供阅读，但其中的服务器路径需要按目标环境核对。

`runtime-reference/server-dist` 用于对照线上编译结果。正常开发应修改 `apps/server/src` 后重新构建，避免源码和编译文件各维护一份业务实现。
