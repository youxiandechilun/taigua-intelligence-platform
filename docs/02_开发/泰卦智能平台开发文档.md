# 泰卦智能平台开发文档

版本 v0.1  
更新日期 2026年11月12日  
实施状态 开发中

## 项目目标

在现有源码上完成平台主站、电销、社媒矩阵、私信拓客和独立站五个系统。主站统一管理商户身份、权限、服务配置和点数，各业务系统完成自己的操作与记录。国内私信拓客由我方开发，海外版复用现有实现并接入平台。

开发、构建、测试和截图通过后台命令及无头浏览器执行。各模块完成后记录实际运行结果，最终交付源码、升级脚本、自检工具和部署资料，由部署者完成环境配置。

## 需求依据和已确认决策

- 功能范围依据项目需求清单整理，当前实现状态见根目录 README。
- 平台需求包括主页后台管理接口及密钥、沿用主页风格、逐模块截图和整体源码交付。
- 总交接说明用于核对平台统一登录、点数计费、商户隔离及现有实现。缺失功能、接口、结构和必要升级脚本由我方完成。
- 个人微信采用人工确认联系任务。系统提供候选名单、联系文案、任务、结果登记和跟进提醒。
- 平台管理员统一管理服务配置与收费参数。商户查看自身数据和用量。
- 收费参数后台可调。长任务先冻结额度，按实际成功量结算，取消或失败释放未使用额度。
- 海外社媒与海外拓客的微信或WhatsApp命名，结合原清单上下文整理，渠道配置分别保存。
- 现有工程保留各自技术栈。主站使用SQLite，电销使用PostgreSQL和Redis，社媒沿用SQLite，拓客先兼容现有JSON数据。

## 统一身份和接口契约

业务系统通过TAIGUA_PLATFORM_URL访问主站，内部请求使用X-Internal-Key头，密钥来自INTERNAL_API_KEY。服务启动配置中保存TAIGUA_AGENT_SLUG。

| 产品 | 标识 |
| --- | --- |
| 国内电销 | ztgh |
| 海外电销 | ztwh |
| 国内社媒 | ztgj |
| 海外社媒 | ztwj |
| 国内拓客 | ztgt |
| 海外拓客 | ztwt |

内部接口沿用交接说明的ok、data、code和msg响应。主站原有公开API继续保持原有调用方使用的code、data和msg结构。

| 方法和路径 | 输入或查询 | 结果 |
| --- | --- | --- |
| POST /api/internal/sso/redeem | token、agent_slug | mid、merchant_name、agent_id、slug、balance、expire_at、external_user_id、session_token |
| POST /api/internal/sso/validate | token为session_token、agent_slug | 当前有效身份，停用或退出返回401 |
| POST /api/internal/points/consume | mid、agent_slug、action、quantity、request_id | request_id、charged、balance |
| POST /api/internal/points/reserve | mid、agent_slug、action、quantity、request_id | hold_id、held、balance |
| POST /api/internal/points/settle | hold_id、actual_quantity | charged、refunded、balance和最终状态 |
| POST /api/internal/points/release | hold_id、reason | released、balance和最终状态 |
| GET /api/internal/merchant/balance | mid | balance、frozen和available |
| GET /api/internal/agents/prices | slug | action、points和daily_cap列表 |
| GET /api/internal/config | slug | model、search、telephony和notifications配置 |

主站提供POST /api/agents/enter生成短期一次性票据。登录同时保留原Bearer调用方式并下发Cookie。生产域名为.taikua.cn，开发环境采用本机Cookie配置。

redeem将父会话关联到子系统会话。子系统服务端保存会话引用，验证停用和退出状态，最长缓存30秒。票据一次性消费，票据使用后再次提交返回401。

### 配置字段

- model包括enabled、base_url、api_key、model和timeout_seconds。
- search包括provider、base_url和api_key。
- telephony包括enabled、provider、base_url、api_key、sip_domain、sip_username、sip_password、caller_id、tts_provider、tts_model和voice_id。
- notifications包括webhook_url。

配置写入受控字段。后台响应对密钥脱敏，内部调用按产品权限读取需要的配置。配置保存产生审计记录，日志只记录变更字段名。

### 计费约束

点数使用整数。可用额度为余额减冻结。扣费、流水和每日用量在同一事务中更新，扣费条件同时检查可用额度。

request_id绑定商户、产品、动作和数量。相同业务重试返回已有结果，参数冲突返回409。冻结保存价格快照、到期时间和状态，结算及释放可重复调用。过期冻结由维护任务回收。

默认动作包括lead_search、ai_generate、mail_send、wa_send、social_publish、call_minute和site_generate，价格及日限额可在后台调整。默认价格用于本地验证，上线运营价格由后台管理。

业务发送或拨打发生前预留额度，成功后结算。结果不确定的动作保存待核对状态，重启后根据业务单号恢复，避免重复执行或重复收费。

## 数据兼容和迁移

主站在现有商户和会话表上增加冻结、版本、有效期、撤销和来源字段，新增票据、子会话、价格、流水、冻结单、每日用量和身份映射。升级过程记录版本并支持重复执行。

拓客保留已有JSON结构及租户辅助方法，所有集合读写和后台任务带商户上下文。旧记录按已有默认租户归属迁移，已有版本号也执行缺失归属修复。

社媒在员工与会话中加入商户归属，员工工作区访问同时校验当前商户。电销利用现有组织和成员映射平台商户，原钱包账本记录流水投影和供应商成本。

升级及测试使用开发数据库和合成数据。交付脚本保留现有业务账号及历史记录。

## 验证安排

- 主站检查旧数据升级、登录Cookie、单次换票、停用和退出失效。
- 建立两个商户及各自员工，检查列表、详情、修改、批量、后台任务和文件访问的隔离。
- 对同一扣费业务重复提交，并发20个请求，核对余额、冻结和流水。
- 检查冻结到期、任务取消、部分成功、结算重试及参数冲突。
- 使用真实HTTP和本地数据库验证业务契约。外部供应商测试服务记录为模拟验证，真实通道另行记录联通结果。
- 检查国内拓客从候选到联系、回复、留资和跟进的完整流程。
- 检查电销及社媒的配置缺失、接口失败、暂停、重试及恢复。
- 检查独立站两商户、多语言、公开HTML、sitemap、canonical、结构化数据、询盘和发布回滚。
- 通过无头浏览器验证页面和截图，截图使用合成业务数据。
